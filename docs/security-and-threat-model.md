# Security and threat model

Status: covers the local build through Phase 8 (local containers and CI definition
included). Cloud-specific controls (WAF, managed keys, network policy) are planned in
docs/deployment.md and are not implemented. "Evidence" names the automated test or drill
that exercises the control; a control without one is marked as such.

## Assets

1. Tenant business data: purchase orders, receipts, invoices, supplier messages, uploads.
2. Decisions and their integrity: findings, citations, approvals, operations, audit trail.
3. Authority: user sessions, approval rights, worker/MCP service credentials, delegation keys.
4. External effects: follow-up tasks created in a task system (simulator or GitHub sandbox).
5. Secrets: OIDC client secrets, simulator master secret, delegation signing key, API keys.

## Actors and trust boundaries

| Actor | Trusted for | Not trusted for |
|---|---|---|
| Signed-in user (browser) | Actions their server-side membership permits | Tenant id, role, tier, approver identity in any request field |
| Another tenant's user | Nothing in this tenant | — |
| Supplier / document author | Being the source of a document | Any instruction inside it; field values beyond what parsing and rules accept |
| Model (mock, hosted, local) | Proposing text and evidence requests | Arithmetic, permissions, action parameters, conclusions without citations |
| Worker / MCP services | Their own scoped service identity | Acting as a user beyond a signed, short-lived delegation |
| Source and task systems | Returning data and outcomes | Consistency after a timeout (reconciled, or marked `outcome_unknown`) |

Boundaries: browser ⇄ API (cookie session + CSRF); API/worker ⇄ PostgreSQL (non-bypass RLS
roles); worker ⇄ MCP services (Keycloak service token + Ed25519 delegation); worker/MCP ⇄
simulator / GitHub (HMAC or token, allow-listed repository); hosted model provider
(redacted prompts, opt-in, spend ceiling).

| T2 | Tenant context leaking through pooled connections | Transaction-local `set_config`, re-applied after every BEGIN; single-connection pool test across tenants and "no tenant" | `test_rls.py` pooled tests, `test_hardening.py::test_worker_connection_reuse_does_not_carry_tenant_context` | — |
| T3 | Retrieval ranks or returns another tenant's text | Authorization (RLS + allowed version ids) in the SQL `WHERE`, before `ts_rank` | `test_retrieval_authorizes_before_ranking_across_tenants` | Lexical only; semantic retrieval not built, so its isolation is untested |
| T4 | Artifact path traversal / cross-tenant artifact read | Keys are `<tenant>/<aa>/<sha256>`, validated and resolved inside the tenant root | `test_artifact_keys_cannot_cross_tenants_or_escape_the_store` | Same keys and checks in the S3 store (`tests/evidence/test_s3_store.py`, `tests/integration/test_s3_store.py`); one bucket and task role serve all tenants, so separation relies on these checks and the RLS-protected manifest, not per-tenant IAM |

| T7 | Prompt injection in documents | Documents are data; model output validated (schema, citations exist, numbers supported, numbers in their stated roles and units, comparisons that hold, dates the evidence shows, prohibited claims, route agreement); action parameters loaded server-side; approvals required | `test_injected_document_instructions_cannot_change_authority`, `tests/agents/test_routing_and_validation.py` | A validated but misleading explanation can still reach a human; the approval step is the control |
| T8 | CSRF / cross-origin abuse | Synchronizer token + Origin check on cookie writes; CORS allow-list; SameSite=Lax cookie | `test_csrf_token_required_for_writes`, `test_cors_allows_only_configured_origin` | — |
| T9 | Session theft | HttpOnly cookie with hashed server-side session, 8 h absolute / 30 min idle, logout revokes | `test_oidc_login.py` | Local dev runs on http; staging must set Secure cookies behind TLS |
| T10 | Stale or replayed approval executes | Approval bound to version, payload digest, policy, source manifest, expiry; rechecked before every new write, retries included (F01); single consumption; the Casework MCP tool admits a create with the same check when the request reaches it, once per executor attempt, and sends only the sealed text (A05) | `test_approvals_execution.py` (18), `test_policy_published_before_dispatch_cancels_the_operation`, `test_casework_admission.py` | A change committed after the admission check is too late for that write; a request the provider accepted cannot be withdrawn |
| T11 | Duplicate external effect after timeout | Attempt ledger before the call; capability-driven reconciliation; `outcome_unknown` + human review when lookup is eventual/absent; without idempotency keys a lookup that finds nothing proves absence only after the create's request deadline (which the provider must honour) has passed, so a create still in flight is never sent again | `test_approvals_execution.py` timeout-after-commit, `test_a_create_still_in_flight_is_not_proved_absent_and_sent_again[deadlines, no deadlines]`, `test_github_execution.py` | At-least-once delivery; exactly-once is not claimed; the deadline guarantee is the provider's (only the simulator implements it) |
| T12 | Service identity used as a user | Two credentials per MCP call (service token audience + allow-list, delegation naming tenant, principal, case/operation, tools; ≤ 5 min); membership re-read server-side; an issue time up to 30 s ahead is a clock difference and accepted, expiry is exact | `test_mcp.py` (7 denial cases), `tests/mcp/test_clock_skew.py`, `tests/mcp/test_verifier_keys.py` | Delegation signing key is a local file in dev; staging needs a managed key. Verifying services hold public keys only (key ids, rotation overlap, A06); the development compose volume still holds both keys |
| T13 | Tier used as authority | Tiers gate features only; roles and membership gate actions | `test_tenant_settings_respect_roles_and_tiers`, `test_tier_entitlement_gates_model_modes` | — |
| T14 | Secrets or identifiers in logs | Redacting filter on every handler incl. uvicorn access logs (OIDC `code`/`state`) and tracebacks | `tests/privacy/test_log_redaction.py` | Pattern-based; telemetry export not built yet (Phase 8) |
| T15 | Sensitive data sent to a hosted model; spend beyond the ceiling | Opt-in per run, tier gate, pattern redaction, local-required policy with no hosted fallback; spend ceiling and daily call quota reserved under the organization's lock before a call is sent, the estimate kept charged when no usage comes back (F06) | `tests/agents`, `test_local_required_policy_blocks_model_without_hosted_fallback`, `test_spend_reservations.py` | Redaction is not anonymization; the cost estimate is not a guaranteed bound |
| T16 | Retained content kept longer than policy; retention destroys content still in use | Retention sweep deletes bytes/text and records the deletion; shared bytes go only when no live artifact uses them, after the rows commit (F08) | `test_retention_deletes_protected_content_and_says_so`, `test_retention_schedule.py`, `test_retention_uses_the_database_clock_not_a_drifting_app_clock`, `test_retention_blobs.py` | Backups not covered |
| T17 | Changed source data after investigation | Source manifest digest; new document versions only when bytes change; re-investigation shows the new version | `test_changed_source_document_creates_a_new_version_and_new_evidence_state` | Changes between investigation and approval are caught at dispatch via the manifest |
| T18 | Abuse / brute force | Fixed-window limits shared by all API instances (PostgreSQL, windows aligned by the database clock): every API request counts against its client address before anything else (`rate_limit_per_address_per_minute`; X-Forwarded-For believed only from `trusted_proxies`, nearest non-proxy hop), and a verified user against their own budget after the session check (`rate_limit_per_minute`). An unverified cookie never selects a budget (until 2026-10-22 it did: a fresh random cookie got a fresh budget and a database row, F09). Per-process fallback if the database is unavailable, bounded by an overflow window; body-size limit | `test_rate_limit_and_body_limit`, `test_two_api_instances_share_one_limit`, `test_made_up_cookies_do_not_escape_the_address_limit`, `test_without_the_database_each_process_still_limits`, `tests/api/test_perimeter.py` | Not a DDoS control (one database write per limited request); clients behind one address share its limit; behind a load balancer `trusted_proxies` must name it or every client shares the balancer's address |
| T19 | Forbidden autonomous actions | No payment, invoice posting, bank-detail or PO-modification actions exist; the action registry contains follow-up tasks and local case actions only | code review (`connectors/`, `services/proposals.py`) | — |
| T20 | Telemetry leaks content or identifiers | Spans carry ids, route templates and statuses only (string attributes scrubbed); metric labels bounded (no tenant/case/user ids); logs scrubbed; FastAPI native telemetry disabled | `test_observability.py` (no document text in spans, no UUIDs in labels) | A new span attribute added carelessly is only pattern-scrubbed |
| T21 | Forged trace context from the internet | Each request starts a new trace; `traceparent` from clients is ignored | `test_incoming_trace_context_is_not_trusted` | Internal propagation (API → job) is trusted |
| T22 | Cross-tenant aggregates weaken RLS | `ops.metrics_snapshot()` is SECURITY DEFINER, owned by NOLOGIN `opsbridge_ops_reader` with column-level SELECT on status/timestamp columns; returns counts and ages only; app/worker may execute it, nothing else | `test_aggregate_state_reports_backlog_while_rls_still_hides_rows` | Counts across tenants are visible to operators of the metrics endpoint |
| T23 | `/metrics` scraped by outsiders | Aggregate data only; optional bearer token; bound to localhost locally and to the private network in the staging plan | `test_metrics_endpoint_can_require_a_token` | Token is static; rotate with the deployment |
| T24 | Secrets in images or CI | Allow-list build context (no `.env`, keys, `var/`); CI uses no secrets, `contents: read`, actions pinned to SHAs, runs on PRs to main or manual dispatch | image inspected (no `.env`); actionlint; hosted CI runs without secrets (docs/STATUS.md) | Runner images and apt packages are not pinned |
| T26 | Hostile image in a scanned PDF (decoder bug, decompression bomb, slow OCR) | OCR is off by default. Images are decoded in the PDF worker subprocess (hard timeout) with a 40 MP pixel cap, at most 4 images per page and `ocr_max_pages` pages; tesseract runs with a per-page timeout, one thread, a fixed argument vector and a validated language code, as uid 10001 in a read-only container | `test_an_oversized_image_is_refused_not_decoded`, `test_language_codes_are_validated_before_reaching_the_command_line` | Pillow and tesseract parse untrusted image data in native code; no extra sandbox (seccomp) around them |
| T27 | OCR misreading becomes a business fact | OCR text stays `needs_review`; OCR field values are candidates (`ocr` / `needs_review`), never records; corrections of them are refused | `test_ocr_values_are_shown_for_review_but_never_decide` (a perfect reading of INV-9001 still goes to a person); real OCR misread `ST-150` as `ST-15@` | A person may still act on a misread value they see; the UI labels it |
| T28 | Administrator abuses or races member management | Requires `tenant.manage_members`; the tenant's membership rows are locked and the actor's own authority is re-read under the lock; no one changes their own membership (so an active administrator always remains); roles and action types validated; a revoked or narrowed approver's earlier approvals are refused at dispatch; re-seeding never changes existing memberships; before/after audited, free-text reason kept on the membership row | `test_member_management.py` (8, incl. two administrators demoting each other concurrently and a request in flight after demotion), `e2e/phase6.spec.ts` | Two colluding administrators can still grant each other any role |
| T29 | Someone other than the invited person joins (forwarded or leaked link, unverified address, replay) | 256-bit random token in the URL fragment (never sent to servers, logs or Referer; moved to sessionStorage and removed from the address bar); only its SHA-256 stored; single use and expiry on the database clock; accepted only by a signed-in user whose identity provider verified the invited address (`email_verified` from the ID token); the inviter must still be allowed to manage members; RLS shows an invitation outside its tenant only to the matching token hash, read-only | `test_invitations.py` (7), `test_oidc_login.py::test_invitations_trust_only_an_address_the_provider_verified` (real Keycloak), `e2e/invitations.spec.ts` | Relies on the identity provider's email verification; whoever controls the invited mailbox at the provider can join; OpsBridge sends no email, so the administrator delivers the link |
| T30 | An approved action is redirected or sent with different text (tenant connector setting, sandbox repository or redaction rules change after drafting or approval) | Destination (connector + organization/repository, no credentials) and the exact outgoing text are part of the approved payload and shown before approval; approving and every dispatch recompute both and refuse on any difference; dispatch sends the approved text; the attempt records the full request incl. body | `test_a_settings_change_after_drafting_cannot_redirect_the_approval`, `test_dispatch_refuses_when_destination_or_outgoing_text_changed_after_approval[*]`, `test_attempt_requests_and_responses_are_kept_and_match_their_digests` | GitHub credentials and repository are deployment-wide sandbox settings, not versioned tenant connections |
| T31 | A decision rests on changed evidence (correction, upload, a source version ingested for another case) without a re-run, or a case is resolved on a stale result | Each investigation records its evidence state before matching; proposing, approving, every dispatch and resolving recompute it and refuse a stale result; dispatch rechecks under the case lock corrections take; resolution also checks the effective policy | `tests/integration/test_evidence_freshness.py` (7) | The digest is local; a source change OpsBridge has not fetched is bounded only by the source-age limit (T36) |
| T32 | Another supplier's invoice with the same number, or a look-alike number, stands in for this one; a reused idempotency key returns a different case | Current invoices are unique per supplier and number; a case may name its supplier, and an unnamed one stops for review when two suppliers' invoices carry the number; identifiers keep punctuation and leading zeros, look-alikes need explicit confirmation; a key reused with a different request is refused | `tests/integration/test_business_identity.py` (3) | One legal entity and one purchasing source per tenant are assumed; credit-note numbering is not modelled |
| T33 | An unreadable replacement document leaves old facts current | A newer version that yields no records (rejected, needs review, OCR only) supersedes the earlier records; a refused current document sends the run to manual review | `tests/integration/test_source_replacement.py` (3) | Parsers are time-bounded but not memory- or process-isolated |
| T34 | Two workers run one investigation, or a worker that lost its job overwrites results | The investigation handler holds its job's lease: every durable write is fenced, the lease is renewed while a step runs for at most `investigation_step_limit_seconds`, finalization decides under the case lock; a job whose worker died on every attempt is given up, not re-claimed forever (F05) | `test_investigation_leases.py` (4) | A model call already in flight on a stuck worker still happens (and is recorded) |
| T36 | A decision rests on part of the source's data or on data the source has withdrawn: a listing cut at its first page, a receipt deleted, voided or moved to another PO that keeps counting, or purchasing data of any age | Listings follow every page or report themselves incomplete (manual review); a record the source no longer holds stops being current; each investigation records when it read the source and may be acted on for `source_max_age_hours` (24); reading has one time budget per investigation (`source_collection_seconds`), and a collection cut short concludes nothing (A15); credentials errors and outages are never read as "not found" | `tests/integration/test_purchasing_source.py` (6), `tests/contracts/test_purchasing_source_contract.py` (21), `test_collection_budget.py` (2) | Only the simulator implements the contract; no real purchasing system has been tested. A source that changes without OpsBridge re-reading it is still trusted for up to the age limit |
| T37 | A changed or compromised task connection redirects approved work, writes to an arbitrary repository, or keeps using a revoked credential | Approvals bind the connection's destination; a moved connection makes them stale; dispatch builds its connector from the approved destination; repositories must be on the deployment allowlist; credentials are references to the secret store, never stored or shown, and only references the deployment registered for the tenant and repository can be chosen or read (A06); revoking stops every new write and every further use of that credential; each change is versioned and audited with a reason | `tests/integration/test_task_connections.py` (4), `test_credential_registry.py` (5), `test_a_settings_change_after_drafting_cannot_redirect_the_approval`, `test_dispatch_refuses_when_destination_or_outgoing_text_changed_after_approval[connector]` | The secret store is environment variables here; one active connection per tenant; GitHub live writes still need the deployment switch and are not live-validated |
| T35 | Altered evidence served as the original | Local reads verify the digest in the key (as S3 reads did); an altered original answers `evidence_integrity_failed` and is logged (F16) | `test_local_store.py`, `test_an_altered_original_is_refused_not_served` | Detects change, cannot recover it: restore from a backup |
| T25 | Container compromise blast radius | Non-root uid 10001; read-only root filesystem with `/tmp` tmpfs; all default capabilities dropped; `no-new-privileges`; only the `/app/var` volume writable; internal services unpublished; MCP DNS-rebinding protection with explicit allowed hosts | hardened clean-launch drill: root-filesystem write refused, 12 browser tests passed (docs/operations.md) | No custom seccomp/AppArmor profile beyond engine defaults; the shared `/app/var` volume is writable by every app container |

## Out of scope for v1

Custom identity provider, WAF/DDoS protection, HSM-backed keys, malware scanning, data-loss
prevention, formal compliance claims. These are deployment or organizational controls and
are listed in the staging plan as prerequisites, not as implemented features.
